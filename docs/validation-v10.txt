Cam_align v10 — corrected goal and full-board association audit
Date: 2026-10-20 (Asia/Seoul)

Correction
----------
The v9 completion report incorrectly used matched + partial as the numerator.
The requested goal was matched boards >=90% of ALL captures. v9 achieved only
57/76 = 75.0%, not 90%. The old partial-inclusive 70/76 figure did NOT meet it.

Correct metric, unchanged acceptance gates
-----------------------------------------
Denominator: all 76 input capture pairs, including failed/unconfirmed/partial.
Numerator: ONLY identity.state == matched.
Partial boards are never counted as successes, even when their location is right.
Matched retains the existing structural gates (size 70-140%, occupied support
cells >=75%, rectangularity >=70%, edge support >=55%, quadrilateral support
>=80%, normal stability <=15 degrees, flatness <=0.20) AND board-coordinate
8x8 cell coverage >=60%, plus the existing plausibility/ambiguity tests.
The requested 90% here is the fraction of matched CAPTURES, not a claim of
90% per-board pixel recovery or complete removal of occlusions/missing points.

Implementation
--------------
1. Add source-only multiscale range-discontinuity connected components to the
   RANSAC seeds. Median windows 5/9 and gradient levels propose masks only.
   All final fits, quality tests and exports use original 3D samples.
2. Refit independent pairs of physically continuous source supports. Do not
   recursively merge through another fragment/hand. Retain invalid holes.
   Apply the same complete_support and support_quality checks after refitting.
3. Among plausible hypotheses of the SAME object, prefer a complete eligible
   one within the existing ambiguity score margin instead of a quieter strip.
   This does not set partial.support_quality.eligible to true or relabel it.
4. Re-estimate NSL-only dimensional correction BEFORE RT, then grouped RANSAC
   and linear-loss LM, including all four time-block-excluded models.
5. UI, logs, saved RT metadata and integration regression explicitly exclude
   partials. The 76-frame GUI regression fails unless matched >=69.

No changes to support_quality thresholds or candidate_evidence gates.
No fixed camera baseline, image position, manual ROI or timestamp-specific rule.
No RGB-based point trimming, synthetic points or color-forcing board masks.
Normals are fitted from measured XYZ, not boundary lines in a 2D image.

Matching availability is not alignment precision
------------------------------------------------
Same FIXED 57 v9-matched supports evaluated with both time-block-excluded models:
                              v9            v10
Median point-plane RMS        17.6503 mm     15.8251 mm
Median bidirectional boundary  9.4347 px       9.7706 px
Median outside-board fraction  3.5529%         4.8069%

The plane residual improves but boundary/outside metrics slightly worsen.
Therefore this release does NOT claim that every RGB alignment metric improved.
These are internal consistency/projection metrics, not physical ground truth.
The current dataset informed algorithm development; cross-fitting is not a
fully untouched external test. No real captures with a different camera/layout
are available, so generalization remains unverified.
